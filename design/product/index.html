Firsthand Design summary. Revised 15 Nov 2026. Nothing built yet.

Free and open source. Working name, pending a trademark check

The agent writes the code. You keep the judgment.

Firsthand installs into the coding agent you already use: Claude Code, Codex, Cursor, Copilot, Gemini CLI and others. At the few points where the work needs a human decision, it asks for one short call. Then it runs a real check on your project and shows what happened next to what you said.

It does not quiz you on code. It does not train prompting, context files, permissions or agent settings, because those change with each tool release.

By default it asks once a day at most, never makes the agent wait, and goes quiet on a skill once your calls prove reliable. A one-word skip always works. Facts are never held behind a question.

What it is

Three parts

1

In the build

Thirteen moments, each tied to something that happened: the agent says done, a test fails, a migration cannot be undone, a change has grown too large. You make a call. A check runs.

2

The Room

A local web app the engine serves. It keeps your questions, results, notes, decisions and drills. Answers typed there do not pass through the agent. It also opens on a paired phone.

3

The record

A git repo on your machine, outside any project, with no remote unless you ask. No server, no telemetry, no account.

Why it is built this way: the research in SKILLS.md reports that delegating work can weaken the understanding needed to check it, that committing to a prediction before seeing the answer keeps learning, and that prompts should be rare, varied, matched to the person and tied to checkable feedback. It also says no study has tested practice of this kind as an intervention. The design does not wait for one: every result is a true fact about your own project, which is useful either way.

The moments

When it asks, what you do, and the check

Every moment has a trigger, one action from you, and a check that gives the feedback. Triggers are tests on things the engine can observe: hook events, the git diff, test results. Never a model's reading.

Ten of the thirteen need only git and a test command. Way back and Invariant need support for the project's migration tool, built first for pytest with Alembic or Django. Silent failure needs a capture shim per language, Python first. At install, a "What works here" note says which moments can run in your project.

Not interruptions

  • How sure. One optional tap after a call is locked: Sure or Not sure.
  • Time call. A row in the Room during a change. You pick a band for the share of active time that will come after the agent first finishes. The timeline checks it when the change lands.
  • Hazard line. Prints in the agent at once, with no question, when an irreversible command is about to run against a target that is not local.
  • Fact line and notes. A fact line prints when a check finds something on a high-stakes change. Everything else is a note in the Room.
  • Eight drills in the Room, on your own history: Proof audit, Map it, Replay, Rebrief, Supervise a past run, Split a past change, Break it, Looking back.

How feedback works

  • A call, then what happened. You answer before the result is shown. The result says Matched or Did not match, what you said, the one fact that matters, and where to pick the build back up.
  • The check is something that ran. Each run has a control: the same tests on an unchanged scratch copy must behave as they do on the real tree, or nothing is asked.
  • A miss shows the cue. One mechanical line on what would have shown it.
  • Facts first. A finding reaches you whether you answer, skip or ignore the question. It also goes to the agent as one line, so the build benefits. Your call, and whether it matched, never go to the agent.
  • "Don't know" is never a miss. A call is scored when it was made before the result was shown, a real check produced the outcome, and the engine chose the case.
  • A model is the fallback. It is used only where text must be read or written, under the accuracy rules: a separate context, keys that cite their source, a blind check of every key, two readings that must agree. Otherwise the call is unscored.
  • Questions fade. Three matched calls on a skill give the one-line form. A skill at Reliable, or marked "I do this already", goes quiet. Its checks still run and post notes.
  • Levels are coarse. Too few calls, Shown, Reliable. They never go down. Each row leads with counts, and with what always giving one answer would have scored.
  • Recall supports, it does not lead. An idea is scheduled only after a miss, a "don't know" or an unsure match. It comes back at 7, 21, 60 and 180 days as a new case with a real key. At most three reviews a day, and at most one reminder.
The build always wins. One question a day by default, one per change, nothing on the first prompt of the day, nothing under pressure except a hazard line. Nothing blocks a tool call.

Drills

The eight drills, each with a size and no timer.

  • In the agent: an inline card where the agent can show UI. Otherwise one line of text with the reply words and a Room link.
  • On a phone: the same Room, after one tap on a QR code page. Same network only.
  • Left out on purpose: streaks, points, ranks, and percentages on small counts. Keyboard letter shortcuts are off by default.

Architecture

One engine on your computer. Thin clients around it.

  • Signals. Hooks where the agent has them, the agent's own reports where it does not, and git watch everywhere. Hooks never return a permission decision.
  • Task and base. A task starts at the first prompt after the last finished turn, commit or branch switch. Its base is a snapshot of the tree at that prompt. Every card shows the base and lets you correct it.
  • Checks. They run on a scratch copy built from a snapshot. Old commits run in a container.
  • Keys. One rule in one function: nothing given to the agent carries a result before you have answered. No signing and no key encryption. The record is your own.
  • Same outcome on every agent. The check needs only a shell and git, and an answer counts the same wherever it is typed. Richer agents change timing and convenience.
  • Cloud sessions. No engine runs there and there is no carry branch. firsthand import reviews the fetched work at your next local session.
  • Privacy. No server, no telemetry. The install copy names everything that leaves the machine.

Open decisions

Seven calls for you, each with a recommendation

A
Questions a day by default
The caps of 3 reviews and 1 reminder a day are settled. The number of questions asked while building is not.
Recommend: 1 a day, which you can raise to 3. The reviews found that with 3, the lines the tool printed in a day came to about double that.
cadence
B
Chat replies count the same as Room answers
The earlier approach scored only answers typed in the Room.
Recommend: Yes. The key is a run the agent cannot change, the record is your own, and Room-only scoring breaks the same outcome on agents without hooks. The Room still keeps an answer out of the chat.
scoring
C
Findings go to the agent by default
After you answer or skip, a fact such as "this test passes without the change" is given to the agent as one line.
Recommend: Yes, with a switch in Settings. The build should benefit. Your call stays private.
build
D
Record encryption on work computers
The first builds store plain files.
Recommend: Not in the first builds. Say plainly at install that whoever manages the computer can read the record. Add encryption together with the remote feature.
privacy
E
The phone over plain HTTP on the local network
A browser gives such a page no crypto and no offline mode, so cards could be read by someone attacking that network.
Recommend: Build it last, state the limit on the pairing screen, keep it off by default on work computers.
phone
F
Licence of this repo
It is MIT today. The decision is Apache-2.0 for code.
Recommend: Switch when the firsthand/ package is added in step 2. Add CC BY 4.0 for the idea catalog and question bank when they are first published.
licence
G
The name
Firsthand needs a trademark check, and the package names reserved on PyPI and npm, before any install line is public.
Recommend: Run the check before step 2 ships. Keep Ownline as the fallback.

Already decided

  1. The record is a local git repo outside any project. No remote unless you ask.
  2. At most 3 reviews a day. At most one reminder a day, at a time you choose.
  3. Keyboard letter shortcuts are off by default. One confirmation tap on the phone is fine.
  4. The same learning outcome on every coding agent surface.
  5. Apache-2.0 for code, CC BY 4.0 for content. A Python engine reusing the existing one.
  6. No carry branch for cloud sessions. An import step instead.
  7. The name Firsthand, pending a trademark check.
