## 1. Nearest neighbours: what do the open-source tools ask, when, at what level, who judges, what is drawn, and what record is kept?

### Takeaway
I read 20 repositories. Quizzing a developer on agent-written code is now a crowded pattern, and three parts the first pass called missing do exist: a quiz before the code is written (quiz-me), prediction-type questions (change-quiz, codebase-quiz, Learning Opportunities), and a record that lasts across sessions (lgtm-quiz, Save Point, comprehension-check, VibeCheck, codecall, quiz-me, codebase-quiz). In every one of them a model writes the question and the answer key, the question is text or multiple choice, and nothing is drawn. The tools that draw (visual-explainer, Plannotator, claude-plan-visualizer) ask for decisions and approvals, never a prediction, and score nothing.

**Details that matter for the gap**

A second model pass drops questions answerable without the diff. Only multiple choice exists today; written answers are on the roadmap. Claude Code only. The commit hook is opt-in and can be skipped with `--no-verify`. - visual-explainer, v0.15.0 on 4 November 2026, MIT, 102 commits, 701 forks. `/generate-visual-plan` tells the agent to draw a "hero" flow with "new and removed parts marked", list claims, mark unconfirmed ones `evidence="guess"`, render, then "wait. Do not build before the response arrives", and "After you build, set each claim's `status` and render again". `references/plans.md` says "the page becomes the build receipt" with `status="built|changed|dropped"`. ### Inferences
- "Who judges" is the clearest dividing line. In all 16 quiz-type tools the answer key comes from a language model. Several say so and warn about it (lgtm-quiz, VibeCheck, Save Point, Learning Opportunities). None checks the developer's answer against a fact computed from the repository.
- The level is mostly lines or single behaviours. System-level questions exist only as an option (lgtm-quiz level 3) or as one question type among several (quiz-gate "location/flow", change-quiz "how it interacts").
- Timing: 14 of the quiz tools run after the change. quiz-me is the only one that asks before the code is written, and it asks about cause and fix at line level, not about system effect.
- Adoption is tiny for quiz tools (0 to 372 stars; most under 20) and large for tools that show and annotate (visual-explainer 11.1k, Plannotator 12.4k) and for Learning Opportunities (2.6k). Developers have taken up tools that help them look and decide far more than tools that test them. This is correlation from star counts, which are a weak measure of use.
- Records exist but each holds model-judged quiz scores. No tool keeps a record of predictions against outcomes.

## 2. Official documentation: what do the agent products do before and after a change?

### Takeaway
Read from the vendors' own pages, every product puts the agent's statement in front of the developer before the change (plan, spec, implementation plan) and the tool's summary after it (walkthrough, guide, diagram). No vendor page describes asking the developer for their own expectation, and none describes a learning feature for professional agent work except Claude Code's two output styles.

### Cited Findings

**Claude Code (Anthropic; sells AI: yes; official documentation, page read 16 November 2026, undated, refers to v2.1.269)**
- Explanatory: "Claude adds short `Insight` blocks that explain the choices behind the code it writes"; the blocks carry "two or three points about your codebase or the code Claude wrote". Learning "also asks you to write some of the code": at "a piece with a real design decision ... it leaves a few lines for you", marks it `TODO(human)`, "then stops and waits", and "responds with one `Insight` about your code". "It's an instruction Claude follows, so nothing enforces it." Styles do not apply to subagents other than forks. — [output styles](https://code.claude.com/docs/en/output-styles)
- Plan mode: "Plan mode tells Claude to research and propose changes without making them." Entered with Shift+Tab, `/plan` or `--permission-mode plan`. "When the plan is ready, Claude presents it and asks how to proceed"; options are approve with auto mode, approve with manual edit review, or "No, keep planning". "Press `Ctrl+G` to open the proposed plan in your default text editor." The page does not mention diagrams or any question to the developer other than approval. — [permission modes](https://code.claude.com/docs/en/permission-modes) (the last sixth of the page was not read)

**Cursor (sells AI: yes; official documentation, page read, undated)**
- Plan mode steps: "Agent asks clarifying questions to understand your requirements", "Researches your codebase", "Creates a comprehensive implementation plan", "You review and edit the plan through chat or markdown files", "Click to build the plan when ready". "Plans are saved by default in your home directory." The docs page does not mention Mermaid diagrams (the first pass cited a changelog for that) and mentions no learning feature. — [Cursor docs, plan mode](https://cursor.com/docs/agent/plan-mode)
- A search of Cursor's 2026 changelog coverage found Ask mode and Plan mode and no learning, teach or explain mode. — [Cursor CLI changelog, 16 January 2026](https://cursor.com/changelog/cli-jan-16-2026) (snippet only)

**GitHub Copilot (sells AI: yes; official documentation, page read, undated)**
- "The plan agent does not make any code changes until the plan is reviewed and approved by you." The plan includes "open questions about ambiguous requirements"; "Review the plan and answer any questions the agent has asked." Marked "public preview" on the Xcode and Eclipse tabs. — [GitHub docs, plan mode](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-plan-mode)
- GitHub's only learning guidance found is manual: disable inline suggestions and add an instructions file reading "I am learning to code. You are to act as a tutor; assume I am a beginner coder." and "Do not provide code snippets". There is no built-in learning mode on that page. — [GitHub docs, setting up Copilot for learning to code](https://docs.github.com/en/get-started/learning-to-code/setting-up-copilot-for-learning-to-code)

**OpenAI Codex (sells AI: yes; official documentation, page read, undated)**

**Kiro (AWS; sells AI: yes; official documentation, "Page updated: November 12, 2026", page read)**

A "Review" button lets the developer comment on passages. "Quick Spec" generates all three "in one pass without approval gates". **GitHub spec-kit (GitHub sells AI; repository read, cloned, last commit 16 November 2026; MIT; 150.1k stars)**
- Flow: `/speckit-constitution`, `/speckit-specify`, `/speckit-plan`, `/speckit-tasks`, `/speckit-implement`, `/speckit-converge`; "Repeat implement and converge until convergence reports `Converged`." `converge` will "Assess the current codebase against the feature's spec, plan, and tasks, then append any remaining unbuilt work as new tasks". `analyze` is "a non-destructive cross-artifact consistency and quality analysis across spec.md, plan.md, and tasks.md". ### Inferences
- Change diagrams are now a default in two paid review products (CodeRabbit, Greptile) and available free in visual-explainer. All are generated by a model from the diff. None of the pages read claims the diagram is computed, and none reports its accuracy.
- The "before" slot is fully occupied by plan approval. quiz-me's README names the weakness of that: approval "is a click, not a demonstration".
- Learning features for professionals inside agents remain: Claude Code's Learning and Explanatory styles (line-level, unenforced, no memory) and nothing in Cursor, Copilot, Codex, Kiro, Antigravity or Devin on the pages read.

## 3. Research prototypes: what has been built and studied for comprehension or learning of agent work?

### Takeaway
A systematic scan (method below) found two prototypes from autumn 2026 that draw an agent's change at system level, Rasoi and Vibe-GUIDE, and one that tracks developer knowledge over time, SHIELD. None includes a prediction by the developer, all three generate their diagram or model with an LLM, and the only one with a controlled comprehension measure (Vibe-GUIDE, 16 developers) found little evidence of a difference. The 2025 Lead-and-Reveal study remains the only prediction-before-reveal system for AI code in the venues scanned, and it is for novices at line level.

### Cited Findings

**How the scan was done (16 November 2026)**
- SIGCHI venues: I downloaded the full programme data for CHI 2024, 2025, 2026; UIST 2024, 2025, 2026; CSCW 2024, 2025, 2026; IUI 2025, 2026 (11 files, 10,216 entries in total) and filtered titles for code, programming, developer and related words, then filtered titles plus abstracts for "cognitive forcing", "friction", "co-audit", prediction before an outcome, agent oversight, trajectories and traces, over-reliance, deskilling and metacognition. — [SIGCHI programme data, e.g. CHI 2026](https://files.sigchi.org/conference/program/CHI/2026) (official programme data; opened and filtered by script; abstracts read for 12 papers)
- Software engineering venues: I downloaded the accepted-paper pages for ICSE 2025 and 2026, FSE 2025 and 2026, ASE 2025 and 2026, ICPC 2026, VL/HCC 2025 and 2026 and filtered about 2,800 titles. — [ICSE 2026 research track](https://conf.researchr.org/track/icse-2026/icse-2026-research-track), [ASE 2026](https://conf.researchr.org/track/ase-2026/ase-2026-research-track), [VL/HCC 2026](https://conf.researchr.org/track/vlhcc-2026/vlhcc-2026-research-papers) (official pages; titles filtered by script, abstracts not read unless on arXiv)
- arXiv: about 40 queries on abstracts through the arXiv API, 2024 onwards, in cs.HC and cs.SE; abstracts read for 29 papers; full text read for three. — [arXiv API](https://export.arxiv.org/api/query?search_query=abs:%22cognitive+forcing%22+AND+abs:code)
- Across the SIGCHI data, the abstract filter for cognitive forcing, friction or prediction with AI code returned one system paper: Kazemitabaar et al., IUI 2025. On arXiv the query "cognitive forcing" with code returned one paper (2603.14225) and "friction" with "AI-generated code" returned one (2410.08922).

**Prototypes that draw an agent's change**
- Rasoi (arXiv, 12 November 2026; Sahni, Kaul, Bhatnagar, Zhang, Liu, Vir): "a design probe that maps how a codebase's architecture evolves after each agent-made edit, letting developers inspect which architectural elements and relationships were added, modified, or removed across multiple levels of abstraction". The map is produced by the agent ("the agent produces a structured representation directly from the codebase"), in C4-style levels, saved as a snapshot per version and compared with the previous one. No step before the edit; no prediction. Study: informal talks with 8 developers, then 12 experienced developers used it on their own codebases for 7 days with daily check-ins and an exit interview. Results (self-report): 10 of 12 reported more confidence in their own understanding, 2 of 12 more trust in the agent, 11 of 12 said the views helped them see how parts connect; participants caught a removed audio cue and a modularisation that had not been applied. One participant was "surprised that 'no new nodes [had] been added or deleted'" after asking for new modules. Limits stated: no comparison condition, small sample, C4 "sometimes too heavy for small projects". "We plan to open-source Rasoi upon acceptance." The authors cite no prior work on visual diffs of agent-made structural change. — [arXiv 2611.16293](https://arxiv.org/abs/2611.16293) (study, preprint, not peer reviewed; sells AI: no; abstract read via API, full text read via fetch tool)
- Vibe-GUIDE (arXiv, 20 September 2026; Chou, Lee, Choudhuri, Ma): an agentic coding interface around "a structural, live, manipulable, and adaptive graph representation organized by functional modules". The graph is made by a model ("the server sends the project files to Claude Sonnet 4.6 with a fixed prompt"), at most eight modules. A developer can select a module and "describe the intended change" before the agent acts; after a change the graph highlights modified elements. Study: randomized, between subjects, 16 developers (8 per group), three cumulative 15-minute tasks, graph versus chat only. Comprehension test of 23 points scored by a model with a rubric, no human rater. Primary comprehension: median 6.0 versus 5.5 of 16, effect δ = +0.03 with interval [−0.49, +0.53], which the paper reads as little evidence of a difference. Relationship questions favoured the graph (δ = +0.45, interval includes zero); exact-location questions favoured chat (δ = −0.45, interval includes zero). Later tasks slowed less with the graph (δ = −0.80 [−0.95, −0.37]). Trust was lower with the graph (median 17 versus 18). — [arXiv 2609.23859](https://arxiv.org/abs/2609.23859) (study, preprint; sells AI: no; abstract and most of full text read)
- CodeVoyager (IUI 2026; UIST 2025 poster): combines call graphs and control-flow graphs with LLM explanations for unfamiliar codebases; exploratory study n=11, then within-subjects n=16 against a chat assistant; "improved code comprehension and increased user trust". About an existing codebase, not an agent's change. — [IUI 2026 programme data](https://files.sigchi.org/conference/program/IUI/2026) (study; abstract read)
- Trailblazer (UIST 2025, "Answering Developer Questions with Annotated Agent-Discovered Program Traces"): an agent traces program flow and returns "interactive, annotated traces"; in a lab study it "helped participants answer questions more efficiently and gain greater familiarity with program flow than an AI question answering baseline". — [UIST 2025 programme data](https://files.sigchi.org/conference/program/UIST/2025) (study; abstract read; sample size not in abstract)
- Vibetrace (arXiv, 3 November 2026): "interactive trace visualization and intervention system" on OpenCode; users can fork execution from an earlier step; "User studies further demonstrate improved accuracy and efficiency over conventional log-based interaction" (no numbers in the abstract). — [arXiv 2611.04466](https://arxiv.org/abs/2611.04466) (study, preprint; abstract read)
- TracePlay (CSCW 2026 poster): one agent trace rendered as Engineer, PM and Designer views; three internal pilot walkthroughs only. — [CSCW 2026 programme data](https://files.sigchi.org/conference/program/CSCW/2026) (abstract read)
- Position paper, CHI 2026 HCXAI workshop: proposes "conformity seeding, reasoning monitoring, and a causal graph interface" against "agentic entropy", the drift between agent actions and architectural intent. No system evaluation. — [arXiv 2604.16323](https://arxiv.org/abs/2604.16323) (position paper; abstract read)

**Prototypes aimed at learning or engagement**
- Lead-and-Reveal / Trace-and-Predict (Kazemitabaar et al., IUI 2025): confirmed present in the IUI 2025 programme; details are in the first pass. — [IUI 2025 programme data](https://files.sigchi.org/conference/program/IUI/2025); [arXiv 2410.08922](https://arxiv.org/abs/2410.08922) (study)
- SHIELD, "Agents That Teach" (ASE 2026 New Ideas track; Accenture Labs): six principles (contextual, grounded, ambient, selective, adaptive, closed-loop: "The system must verify whether the learning has actually been internalized"). A multi-agent VS Code system on Claude Code: the coding agent emits telemetry per change; probes wait in a queue until the developer chooses to answer "in their own words"; a per-developer "Concept Map" (Neo4j) tracks mastered, partial and unfamiliar concepts. After the change, text only, model-judged. "No empirical evaluation"; feedback from internal demonstrations only. — [arXiv 2607.06101](https://arxiv.org/abs/2607.06101) (tool paper, 7 July 2026; Accenture sells AI services; abstract and full text read)
- Cognitive Tours (Storey, 5 November 2026, submitted to ICSE 2027 demos): a web prototype for "curated paths connecting user needs, design decisions, code, tests, and open questions"; humans build the tour, which "deliberately preserves productive friction". The paper defines cognitive debt as a state where "no one can confidently explain how a system works or predict the impact of a change". Evaluation is proposed, not done. — [arXiv 2611.08456](https://arxiv.org/abs/2611.08456) (tool paper; abstract read)
- CodeZoom (arXiv, 7 October 2025): pseudocode layers for exploring and refining generated code; within-subjects n=26 against Claude Code; "a large effect on code comprehension" and "over 90% of participants reported feeling more in control". — [arXiv 2510.06452](https://arxiv.org/abs/2510.06452) (study, preprint; abstract read)
- NaturalEdit (UIST 2026): interactive natural-language summaries linked to code; "a user study with 20 developers shows that it improves comprehension, intent articulation, and validation". — [UIST 2026 programme data](https://files.sigchi.org/conference/program/UIST/2026) (abstract read)
- Soft barriers (ASE 2026): output perturbations that break naive copy-paste; "An exploratory pilot with 18 participants provides early evidence that soft barriers can shift users from direct transfer toward editing and reconstruction". — [arXiv 2608.22638](https://arxiv.org/abs/2608.22638) (study; abstract read)
- FlowCheck (LMPL 2026 workshop): end users state information-flow constraints through the app's interface; these are translated "into deterministic CodeQL analyses"; it flagged all 30 injected violations with no false positives where three frontier models did not reach full accuracy. It is the one system found where a human-stated expectation is checked by a computed fact; the expectation is a constraint, not a prediction, and the users are non-programmers. — [arXiv 2608.28880](https://arxiv.org/abs/2608.28880) (study, 28 August 2026; abstract read)
- Tracybot (6 November 2026): open-source VS Code and Git tool that maps agent-written lines to the prompts that produced them and exports decision records; focus group of 7 and survey of 24, perceived usefulness only. — [arXiv 2611.09395](https://arxiv.org/abs/2611.09395) (tool paper; abstract read)

**Studies that state the need (no tool)**
- Formative study, CHI 2026 Tools for Thought workshop: "cognitive engagement consistently declines as tasks progress, and ... current ACA designs provide limited affordances for reflection, verification, and meaning-making"; the authors propose "cognitive-forcing mechanisms". A search result describes the sample as four software engineers using Cline. — [arXiv 2603.14225](https://arxiv.org/abs/2603.14225) (study; abstract read; sample from snippet only)
- "Plans They Abandon, Reports They Author" (10 September 2026): across 5,851 developer sessions and 355,942 tool calls, an agent's self-report "referred to about one action in eleven, and a reader working from the report alone recovered roughly a fifth of the action log"; reports resembled the stated plan more as execution diverged from it. — [arXiv 2609.12205](https://arxiv.org/abs/2609.12205) (study, preprint; abstract read)
- "Coding with the Enemy" (NeurIPS 2026): over 100 participants in a five-hour task; "83/88 (94%) of developers in the no-monitor conditions fail to detect sabotage", attributed to "minimal code review, plausible cover story, and overtrust in agents". — [arXiv 2606.05647](https://arxiv.org/abs/2606.05647) (study; abstract read)
- "Beyond the Prompt" (27 September 2026): ten experienced developers with Copilot on an unfamiliar codebase; for two of ten, task success and ability to explain split ("one passed most tests but could not explain the solution"). — [arXiv 2609.33712](https://arxiv.org/abs/2609.33712) (study; abstract read)
- Grey-literature review of 76 practitioner sources on cognitive debt (27 October 2026, under review at ICSE-SEIP): practitioners "propose practices such as documenting design rationale, review-sized changes, comprehension gates, and knowledge-sharing rituals". — [arXiv 2610.37888](https://arxiv.org/abs/2610.37888) (review; abstract read)
- Position paper "Humans are Missing from AI Coding Agent Research" (4 July 2026) names "task alignment, verifiability, steerability, and adaptability". — [arXiv 2608.12355](https://arxiv.org/abs/2608.12355) (position paper; abstract read)
- CHI 2026 full papers confirmed in the programme: "Code with Me or for Me?" (first controlled study of developers with coding agents; challenges include "ensuring users adequately understand agent behaviors"); "When Help Hurts: Verification Load and Fatigue with AI Coding Assistants" (N=60). — [CHI 2026 programme data](https://files.sigchi.org/conference/program/CHI/2026) (abstracts read)

### Inferences
- The idea of drawing the system-level effect of each agent edit has arrived in research within the last two months (Rasoi, Vibe-GUIDE). Rasoi is the closest research neighbour to the "outcome diagram" half of the described tool. It differs in three ways: the map is written by the agent, there is no prediction, and what is kept is a history of snapshots, not a record of the developer.
- Rasoi's participants compared the diff with their expectation on their own, after the fact, and were surprised. That is the described tool's mechanism happening informally, which is suggestive but is one quoted participant.
- The only controlled test of a system-level graph against chat for comprehension is small and close to null on its main measure, with a hint that relationship understanding improves and exact-location knowledge falls. This is a caution for any claim that a diagram improves comprehension.
- "Computed, not model-generated" is rare in this literature. FlowCheck is the example, and its result (deterministic check beats model judgement on accuracy) supports that design choice in a different setting.

### Gaps
- DBLP was blocked (bot protection), so I used SIGCHI programme data and conference pages instead. ACM Digital Library was not opened. CHASE 2025 and 2026 pages returned 404. ICPC 2025, ICSE/FSE workshops, SIGCSE, ICER and Koli Calling were not scanned.
- SIGCHI and software-engineering venues were filtered by title words (and abstracts for SIGCHI); a paper with an unusual title could be missed. Software-engineering abstracts were not read except through arXiv.
- UIST 2026, CSCW 2026 and ASE 2026 lists were scanned, but a programme entry does not prove the paper's final content.
- Sample size for Trailblazer and numbers for Vibetrace's user study were not in the abstracts and I did not open the papers.
- No paper found tests prediction before an agent's change with professionals. Given the scan above, I am fairly confident none exists in CHI, UIST, CSCW or IUI through 2026 or on arXiv under the obvious terms; I cannot rule out one under other wording.

## 4. Is there outcome evidence that any learning or explanatory mode works?

### Takeaway
No study with outcome data was found for Claude Code's Learning or Explanatory styles, or for any learning feature inside a coding agent. The outcome evidence that exists is for tutoring-style assistants in courses, and it is mixed: one new randomized trial found the Socratic, context-aware assistant was the least liked and descriptively the worst on comprehension.

### Cited Findings
- Anthropic's randomized trial (page dated 29 January 2026): 52 mostly junior engineers; AI group 50% versus 67% on the quiz (Cohen's d = 0.738, p = 0.01); about two minutes faster, not significant. Engaged patterns scored 65% or more (generation-then-comprehension about 86%, n=2; hybrid code-explanation about 68%, n=3; conceptual inquiry about 65%, n=7); delegation patterns under 40%. The post names Claude Code's Learning and Explanatory modes and ChatGPT Study Mode as designed to foster understanding and does not test them. It says "Cognitive effort—and even getting painfully stuck—is likely important for fostering mastery." Comprehension was measured right after the task only. — [Anthropic research](https://www.anthropic.com/research/AI-assistance-coding-skills); [arXiv 2601.20245](https://arxiv.org/abs/2601.20245) (study; sells AI: yes; page read and abstract read)
- "Guardrails or Roadblocks?" (arXiv, 24 September 2026; Eastwood, Narne, Hilby, Denny, Aggarwal, Kapoor): randomized trial, 132 students in an introductory programming course, four assistants crossing Socratic versus direct instruction with no context versus full context. "Students rated the Socratic AI TA with full context least favorably, reporting significantly lower perceived support for task completion. Descriptively, this condition also showed ... the highest rate of external LLM use, and the lowest proportion of post-task explanations demonstrating full comprehension, though these differences were not statistically significant." "Guardrailed AI TAs are not automatically better for learning." — [arXiv 2609.29995](https://arxiv.org/abs/2609.29995) (study, preprint; sells AI: no; abstract read)
- (Im)Paired Programming (29 July 2026, in-progress preprint): 54 students; agents "harm users' code comprehension and thus do not prepare users to extend their code"; "copy+paste prompts and auto-accepted edits, are linked with lower comprehension"; "Despite self-reported weaker understanding, users still prefer coding agents because they are quick and easy to use." — [arXiv 2607.26375](https://arxiv.org/abs/2607.26375) (study; abstract read)
- Vibe-GUIDE's comprehension result (section 3) is the only controlled outcome for a system-level visual aid with an agent: little evidence of a difference. — [arXiv 2609.23859](https://arxiv.org/abs/2609.23859)
- OpenAI study mode: per search summaries of OpenAI's page, a randomized study of over 300 college students, intention to treat, with roughly 15% higher scores in microeconomics and differences in neuroscience "not distinguishable from students studying with traditional online resources"; analysis ongoing. School subjects, not software. — [OpenAI](https://openai.com/index/understanding-ai-and-learning-outcomes/) (vendor study; sells AI: yes; **could not open: HTTP 403 twice, including with a browser user agent; snippet only**)
- cc-self-train, a curriculum that teaches Claude Code inside Claude Code: pilot with 27 participants, "statistically significant reported self-efficacy gains across all 10 assessed skill areas (p < 0.001)". Self-report, no control group, and about learning the tool, not understanding agent work. — [arXiv 2604.17460](https://arxiv.org/abs/2604.17460) (study, 19 April 2026; abstract read)
- One informal test of Claude Code's five output styles (ten sessions, one small repository, one run per cell, 24 August 2026): only Explanatory and Learning emitted Insight blocks; output length varied about fivefold; the author concludes the presets "control verbosity and proactivity, not comprehension" and states no reader was tested. — [Civitasmass blog](https://civitasmass.com/blog/claude-output-styles-experiment) (anecdote; sells AI: no sign of it; page read)
- A blog claim that "an instructor saw a 65% improvement in code comprehension assessments" with Explanatory mode gives no method or source. — [medianeth.dev](https://www.medianeth.dev/blog/claude-code-learning-features-2025) (anecdote, snippet only; not used)
- "Echoes of AI" (registered report, ICSME 2025): 151 participants, 95% professional; code co-developed with AI assistants was no harder for other developers to evolve; the authors flag "cognitive debt" as future work. Relevant as a null on code-level harm, not on the developer's own understanding. — [arXiv 2507.00788](https://arxiv.org/abs/2507.00788) (study; abstract read)

### Inferences
- The described tool cannot borrow evidence from existing modes: there is none for coding agents.
- The Socratic result is a warning about friction that feels like a roadblock: students routed around it to another model. The quiz tools' own READMEs say the same ("Someone determined to skip understanding can paste the questions into another AI").
- The best-supported claim is narrow: engaged use is associated with better immediate comprehension than delegation (two studies, small cells, not causal for the patterns). Durable skill has not been measured by anyone found.

### Gaps
- OpenAI's study page could not be opened; its numbers are unverified here.
- No usage data found for any learning feature (how many developers turn on Learning style, or keep a quiz tool installed).
- I did not search education venues (SIGCSE, ICER, L@S) systematically.

### Inferences
- The largest stated condition for trust is cheap verification. A computed outcome diagram is a verification aid in that sense, which is a better fit to stated demand than a quiz.
- Fear of losing skills is real but a minority position as a reason to avoid AI (17.1%, single choice), and "less confident in my own problem-solving" was 20% in 2025. The described tool addresses a concern held by roughly one developer in five on these questions, not a majority demand.
- Half of respondents already use AI itself to understand codebases. The described tool asks them to do the opposite for one moment (think first). Combined with the student preference for speed in section 4, voluntary uptake is the main risk.
- With agents writing about half of professionals' code and seniors leading, the audience is not only juniors.

### Inferences

Who could add the missing parts most easily (my judgement, in order):

1. **visual-explainer.** It would need three additions: let the reader mark the hero diagram before the build (it already collects in-page answers and waits), store the marks, and compare them with the "after" render. It would still lack a computed outcome unless it extends its code-walking beyond state machines; today its after-picture is the agent's own status report. Its direction (decisions and review, with a recent fix so that an untouched default is not read as approval) shows care about what the human actually said, which is close in spirit. This is the main competitive risk and also the most natural host or collaborator.
2. **Rasoi**, if released. It has the outcome half (system map before and after each edit) and a field study showing developers already compare the diff with what they expected. Adding a prediction step is a small design change; replacing the agent-written map with a computed one is not.
3. **Plannotator.** It owns the "before" moment across the most agents and has an annotation surface. It would need a system diagram and an outcome side, which is most of the work.
4. **A vendor.** Antigravity already lists "architecture diagrams" among plan artifacts and pauses for review; Claude Code already has a Learning style and plan mode. A "mark what you expect to change" step in plan review is a small product change for either. I found no announcement of one.
5. **lgtm-quiz, Save Point, Learning Opportunities.** They have the record or the pedagogy but no drawing surface and no before-the-change hook; each would need the largest rebuild. Learning Opportunities' author remains the most relevant reviewer for any measurement.

Other points for the report writer:

- The first pass said "nothing asks the developer to commit before the change" and "no tool keeps a model of the developer except lgtm-quiz". Both are too strong. Correct forms: one tool quizzes before the change (line-level, model-judged); at least seven tools keep some cross-session record; none records predictions against computed outcomes.
- The defensible novelty has narrowed to: prediction by marking a diagram; an outcome that is computed; the two shown together; a record of how the two compare over time. "Computed" is the part with the least prior art and the strongest argument, because every neighbour concedes its model-written answers can be wrong.
- "Computed" is also the hardest part. Nobody found has shipped a model-free system-level diagram of an agent's change, so there is no evidence it can be done well across languages; the first pass's point that dependency tools exist (unsourced there) remains unverified here.
- Evidence for the mechanism is still thin and has one new caution: a system graph did not measurably improve comprehension in the only controlled test (n=16), and Socratic friction was disliked and routed around by students (n=132). Evidence in favour is indirect: engaged use is associated with better comprehension, and Rasoi's users valued seeing unexpected structural change.
- Adoption signal from star counts: showing and annotating attracts thousands; testing attracts a handful. A tool whose first impression is "a quiz" is likely to be read as the second kind.
