# Landscape: tools that help developers understand agent work or learn while building with agents (checked 16 November 2026)

Reading conventions for these notes:

- Every product fact was checked on 16 November 2026 unless a different date is given. "Page date" is the date of the page or release where one was visible; "undated" means the page showed none.
- Source type is one of: official documentation, study, survey, anecdote, opinion, secondary (news or comparison blog).
- "Sells AI" says whether the source sells AI tools (a conflict of interest for claims about their own product or about the need for it).
- "Snippet only" means I saw the claim in a search result summary and did not open the page. Treat those as weaker.
- The "described tool" means: a free open-source tool where, before an agent makes a change, the developer predicts at system level what will happen; a diagram of what actually happened is then drawn beside the prediction; skills build over time; nothing is at the level of code lines.

## 1. Learning and explanatory modes inside agents and assistants: what they do, and is there evidence they work?

### Takeaway
Every major vendor now ships a learning mode, but they either explain after the fact (Insight blocks), hand the developer lines of code to write (Claude Code Learning), or tutor school subjects Socratically (ChatGPT study mode, Gemini Guided Learning, Claude learning mode). None asks for a system-level prediction before an agent's change. Evidence that any of the coding modes works is absent; the only outcome evidence is vendor-run trials on school and college subjects, not software work.

### Cited Findings

**Claude Code output styles (Anthropic)**
- Claude Code has four built-in styles besides Default: Proactive, Concise, Explanatory, Learning. Explanatory "adds short `Insight` blocks that explain the choices behind the code it writes"; the blocks appear in the conversation, carry "two or three points about your codebase or the code Claude wrote", and are not written into files. — [Claude Code docs, output styles](https://code.claude.com/docs/en/output-styles) (official documentation; undated, references v2.1.269; sells AI: yes)
- Learning adds the same Insight blocks and "also asks you to write some of the code". Claude does routine implementation and, at "a piece with a real design decision, such as error handling, a data structure, or business logic", leaves "a few lines" marked `TODO(human)`, sends a "Learn by Doing" request (Context / Your Task / Guidance), "then stops and waits", and responds with one Insight on what the developer wrote. — [Claude Code docs, output styles](https://code.claude.com/docs/en/output-styles) (official documentation; sells AI: yes)
- The docs state the limit themselves: "An output style gives Claude instructions to follow. It doesn't guarantee that something always happens or never happens", and "nothing enforces it". Styles do not apply to subagents other than forks. Explanatory and Learning "produce longer responses than Default by design, which increases output tokens". — [Claude Code docs, output styles](https://code.claude.com/docs/en/output-styles) (official documentation; sells AI: yes)
- The docs page gives no evidence of effect on understanding or skill; it makes no such claim. The docs' own custom-style example is a "Diagrams first" style that leads explanations with a Mermaid diagram, which shows diagram-led explanation is a supported pattern but not a built-in one. — [Claude Code docs, output styles](https://code.claude.com/docs/en/output-styles) (official documentation; sells AI: yes)
- What these styles do not do (my reading of the same page): no prediction step, no comparison of expectation with outcome, no persistent record of the developer's skill, and the Learning task is at the level of code lines ("implement the case "document" branch"). — [Claude Code docs, output styles](https://code.claude.com/docs/en/output-styles)

**Claude learning mode (claude.ai)**
- Learning mode launched in April 2025 for Claude for Education and was extended to all claude.ai users from 14 August 2025 as a "Learning" option in the style dropdown; it takes a Socratic approach (questions, challenging assumptions, step-by-step guidance). The same announcement introduced the two Claude Code styles. — [Engadget, Aug 2025](https://www.engadget.com/ai/anthropic-brings-claudes-learning-mode-to-regular-users-and-devs-170018471/); [Tom's Guide](https://www.tomsguide.com/ai/claudes-new-learning-modes-take-on-chatgpts-study-mode-heres-what-they-do) (secondary, snippet only; sells AI: no). I did not find or open Anthropic's own announcement.

**ChatGPT study mode (OpenAI)**
- Launched July 2025. One comparison site reports it "briefly vanished without announcement in April 2026 and returned with upgrades". — [Glasp comparison](https://glasp.ai/articles/ai-study-modes-compared) (secondary, snippet only; sells AI: Glasp sells an AI product). Not confirmed with OpenAI.
- OpenAI published "Understanding AI and learning outcomes" (March 2026) describing a randomized study of 300+ college students preparing for neuroscience and microeconomics exams, with a no-AI control and two study-mode variants; OpenAI says improvements "varied across subjects", sessions were timed to resemble real conditions, onboarding and technical issues cut study time for some, and analysis is ongoing. — [OpenAI](https://openai.com/index/understanding-ai-and-learning-outcomes/) (vendor study; sells AI: yes). The page returned HTTP 403 to my fetch, so this is from search summaries. A secondary outlet gives "about 15% higher" in microeconomics and an inconclusive result in neuroscience — [TechDefused](https://techdefused.com/a/JSEL94g/openai-launches-framework-to-track-how-ai-affects-student-learning-over-time) (secondary, snippet only). I could not verify the 15% figure against the primary page.
- A Stanford SCALE page describes the associated Learning Outcomes Measurement Suite. — [Stanford SCALE](https://scale.stanford.edu/research-in-action/new-tools-understanding-ai-learning-outcomes) (research partner page; snippet only)

**Gemini Guided Learning (Google)**
- Google and Fab AI report a preregistered randomized trial with 1,763 junior secondary students in Sierra Leone (teachers used Gemini in half of weekly maths lessons for eight weeks): intent-to-treat effect +0.258 SD; +0.380 SD for students with 12+ hours of Guided Learning. — [Stanford SCALE repository entry](https://scale.stanford.edu/ai/repository/teaching-gemini-measuring-impact-guided-learning-student-mathematics-progress-sierra) (vendor-partnered study; snippet only; Google sells AI). Published by Google, not peer reviewed as far as I could tell. Subject is school mathematics, not programming.

**Evidence about coding and skill (not about the modes themselves)**
- Anthropic randomized trial, 29 January 2026: 52 mostly junior engineers learning the Trio library; AI group scored 50% on a comprehension quiz vs 67% hand-coding (Cohen's d = 0.738, p = 0.01); speed difference about two minutes and not significant; largest gap on debugging questions. — [Anthropic research](https://www.anthropic.com/research/AI-assistance-coding-skills); paper [arXiv 2601.20245](https://arxiv.org/pdf/2601.20245) (study; sells AI: yes)
- In the same study, interaction pattern mattered: delegation patterns averaged under 40% (AI delegation 39%, progressive reliance 35%, iterative AI debugging 24%; n=4 each); engaged patterns averaged 65%+ (generation-then-comprehension 86%, n=2; hybrid code-explanation 68%, n=3; conceptual inquiry 65%, n=7). The authors say this is association, not causation, and the cells are tiny. — [Anthropic research](https://www.anthropic.com/research/AI-assistance-coding-skills) (study; sells AI: yes)
- The study used a chat sidebar, not an agent; the authors "expect agentic tools to have larger effects". It names Claude Code Learning/Explanatory and ChatGPT Study Mode as designed to foster understanding but did not test them. — [Anthropic research](https://www.anthropic.com/research/AI-assistance-coding-skills) (study; sells AI: yes)
- "(Im)Paired Programming: Coding Agents Improve Productivity but Harm Understanding" (arXiv, 29 July 2026, in-progress preprint; Balepur, Baumler, Chen, Choi, Rudinger, Boyd-Graber): 54 students built a website with either an agent that edits code directly or a chatbot; agents helped finish the task but reduced comprehension and left users less able to extend the code alone; copy-paste prompting and auto-accepting edits were associated with lower comprehension; users reported weaker understanding yet still preferred agents. Authors recommend agents "encourage active engagement". — [arXiv 2607.26375](https://arxiv.org/abs/2607.26375) (study, preprint, not peer reviewed; sells AI: no). I read the abstract only; no effect sizes seen.

**Third-party add-ons to agents for learning**
- "Learning Opportunities" by Dr Cat Hicks: an open-source (CC-BY-4.0) skill for Claude Code and Codex that offers optional 10 to 15 minute exercises after architectural work (new files, schema changes, refactors), with an auto-prompt variant after git commits and an "orient" skill for new repos. — [repo README mirror](https://cdn.jsdelivr.net/gh/DrCatHicks/learning-opportunities@main/README.md); [everydev listing](https://www.everydev.ai/tools/learning-opportunities) (open-source project; published about May 2026 per aggregator dates; snippet only, the README returned HTTP 503 to my fetch; sells AI: no)

### Inferences
- The built-in coding modes are prompt-level instructions with no enforcement, no memory of the developer and no measure of outcome. They operate during the change (Learning's TODO(human)) or after each piece (Insight blocks), never before it.
- The best available causal evidence says how a developer engages matters more than whether AI is used, and that asking for understanding after generation was associated with the highest scores. That supports the direction of the described tool but does not test prediction, diagrams, or agents.
- Trials of study mode and Guided Learning are vendor-run, in school or college subjects, and partly unpublished. They are not evidence about developers supervising agents.

### Gaps
- No study of any kind was found that measures whether Claude Code's Explanatory or Learning style improves comprehension or skill.
- GitHub Copilot features aimed at learning: I did not find a dedicated learning mode in this session and did not verify its absence against current GitHub docs. Same for Cursor: no learning mode found, absence not verified.
- I could not open OpenAI's study page (403) or the Learning Opportunities README (503), so the exercise types in that skill (for example whether it uses prediction or retrieval practice) are unverified. This matters: it is a possible near neighbour and should be read directly.
- Anthropic's own announcement of learning mode was not opened; dates come from news coverage.

## 2. Tools that explain or visualise agent work and changes

### Takeaway
There is a crowded field of after-the-fact explainers (PR walkthroughs with sequence diagrams, visual diff reviews, session traces) and before-the-fact plan views (plan modes with Mermaid). All of them show the developer something; none asks the developer to commit to an expectation first, and none sets a prediction beside the outcome.

### Cited Findings

**Plan modes (before the change)**
- Cursor: Plan Mode supports inline Mermaid diagrams streamed into plans (Cursor 2.2 changelog); the CLI (18 February 2026) renders Mermaid as ASCII (flowchart, sequence, state, class, ER) and offers a build-in-cloud or build-locally menu after a plan. — [Cursor changelog 2.2](https://cursor.com/changelog/2-2); [Cursor CLI changelog 18 Feb 2026](https://cursor.com/changelog/cli-feb-18-2026) (official changelog, snippet only; sells AI: yes)
- Users report rendering bugs in plan diagrams (cannot expand diagrams in 2.4.22; older bundled Mermaid lacks C4Container). — [Cursor forum](https://forum.cursor.com/t/on-version-2-4-22-i-no-longer-can-expand-diagrams-in-a-plan-preview/150264); [Cursor forum](https://forum.cursor.com/t/built-in-mermaid-renderer-doesnt-support-c4container-diagrams-older-mermaid-version-bundled/162935) (anecdote, snippet only)
- GitHub Copilot: plan mode is in public preview; in the CLI (changelog 21 January 2026) Shift+Tab toggles it and Copilot "asks clarifying questions" and builds a structured plan before writing code; public preview in JetBrains, Eclipse and Xcode from 18 November 2025. — [GitHub docs](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-plan-mode); [GitHub changelog 21 Jan 2026](https://github.blog/changelog/2026-01-21-github-copilot-cli-plan-before-you-build-steer-as-you-go/); [GitHub changelog 18 Nov 2025](https://github.blog/changelog/2025-11-18-plan-mode-in-github-copilot-now-in-public-preview-in-jetbrains-eclipse-and-xcode/) (official, snippet only; sells AI: yes)
- Claude Code has a plan mode (the output-styles page says the Proactive style "doesn't switch to plan mode unless you ask for a plan"). — [Claude Code docs](https://code.claude.com/docs/en/output-styles) (official; sells AI: yes). I did not open the plan-mode page itself.
- claude-plan-visualizer (omril321): MIT Claude Code plugin that turns a markdown plan into one HTML file with a BEFORE/AFTER layout, a Mermaid architecture diagram, diff-coloured components, key decisions and risks, plus annotations to send back to the agent. It visualises the plan only: it does not compare plan with what was built, and the user predicts nothing. 9 stars, 3 commits. — [GitHub](https://github.com/omril321/claude-plan-visualizer) (open-source project; undated; sells AI: no)

**PR and diff explainers (after the change)**
- CodeRabbit: posts a "walkthrough" on each PR with a high-level summary, changed-files table and Mermaid sequence diagrams "for PRs that change component interactions" (setting `sequence_diagrams`, default true; also on request via `@coderabbitai generate sequence diagram`). Its newer "Change Stack" interface generates diagrams inline "for layers where a visual earns its place" (sequence diagrams, state machines, ERDs). — [CodeRabbit docs, walkthroughs](https://docs.coderabbit.ai/pr-reviews/walkthroughs); [CodeRabbit docs, Change Stack](https://docs.coderabbit.ai/pr-reviews/change-stack) (official documentation, snippet only; sells AI: yes)
- Pricing from secondary comparison blogs, which disagree: CodeRabbit $24 or $30 per developer per month; Greptile Pro $30 per seat with 50 reviews then $1 each; Graphite $20 to $40 per user; Cursor Bugbot moved to roughly $1.00 to $1.50 per review in June 2026 or is bundled in a $40 Teams plan, GitHub only. — [Dupple](https://dupple.com/learn/best-ai-code-review-tools); [DEV roundup](https://dev.to/heraldofsolace/the-best-ai-code-review-tools-of-2026-2mb3) (secondary, snippet only; not verified against vendor pricing pages)
- Devin Review (Cognition): "turns large, complex GitHub PRs into intuitively organized diffs and precise explanations"; auto-review on PR open, new commits or reviewer assignment; Devin can auto-fix flagged bugs. — [Cognition blog](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin) (vendor blog, snippet only, undated; sells AI: yes). No evidence found that it draws diagrams.
- visual-explainer (nicobailon): MIT agent skill, 11.1k stars, that renders HTML pages for diagrams, diff reviews and plans. Commands include `/diff-review` ("visual diff review with architecture comparison and code review"), `/generate-visual-plan` (a plan the user responds to in the page, "plus a view of what was built afterward"), `/plan-review`, `/project-recap` ("mental model snapshot"), `/fact-check`, `/state-machine`. Works with Claude Code, Codex CLI, Cursor, OpenCode, Copilot and others at varying depth. It asks for decisions and accept/reject, not predictions or quizzes. — [GitHub](https://github.com/nicobailon/visual-explainer) (open-source project; © 2026; sells AI: no)
- Other open-source diagram plugins for agents exist: claude-d2-diagrams (D2 diagrams from the codebase, flags drift), kenkyl/visualizer (Mermaid from a checked JSON model), archify, diagram-design, and a plugin said to "diff a PR to highlight structural changes". — [claude-d2-diagrams](https://github.com/heathdutton/claude-d2-diagrams); [kenkyl/visualizer](https://github.com/kenkyl/visualizer); [archify](https://github.com/tt-a1i/archify); [engineer-design-diagram listing](https://www.claudepluginhub.com/plugins/jeremylongshore-engineer-design-diagram-plugins-devops-engineer-design-diagram) (open-source projects, snippet only)

**Session records and traces**
- Agent Trace (Cursor): an open, vendor-neutral specification (v0.1.0, RFC status, January 2026, CC BY 4.0) for recording which code ranges came from AI and linking them to sessions. It is a data format for attribution, not a product and not an explanation. Thoughtworks Technology Radar lists it. — [GitHub cursor/agent-trace](https://github.com/cursor/agent-trace); [agent-trace.dev](https://agent-trace.dev/); [Thoughtworks Radar](https://www.thoughtworks.com/radar/platforms/agent-trace) (specification / opinion, snippet only)
- Entire "Checkpoints": a CLI that stores agent context in Git on a separate branch (`entire/checkpoints/v1`); supports Claude Code and Gemini CLI, with Cursor support added but without rewind/resume; one reviewer notes traces are only seen "when you explicitly look" and that switching agents mid-task leaves a gap. — [Entire blog](https://entire.io/blog/entire-dispatch-0x0003) (vendor blog; sells AI tooling: yes); [forum review](https://tianpan.co/forum/t/i-tried-entires-checkpoints-cli-for-a-week-here-is-what-the-ai-reasoning-traces-actually-look-like/859) (anecdote, snippet only)

### Inferences
- "Diagram of what changed" is no longer novel on its own: CodeRabbit does it on PRs by default, and free open-source skills do it locally across agents. The described tool cannot differentiate on drawing the diagram.
- visual-explainer's `/generate-visual-plan` is the closest thing found to a before-and-after pairing (plan view, then "what was built"). The difference is whose expectation is on the page: it shows the agent's plan against the result, not the developer's own prediction, and it keeps no record of the developer.
- Plan approval is a weak form of commitment: the developer reads and accepts the agent's statement instead of producing their own. Nothing in the docs seen measures whether the developer understood the plan.

### Gaps
- Walkthrough generators as a category (for example guided code tours of a change) and session replay viewers (SpecStory and similar) were searched but returned nothing I could cite; not verified either way.
- Graphite, Greptile, Copilot code review and Copilot PR summaries: I confirmed they exist only via secondary roundups and a docs index; I did not verify current features or whether any draws diagrams.
- Whether CodeRabbit's diagrams are accurate or useful to reviewers: no independent evaluation found.
- Claude Code plan mode details were not checked against its own docs page.

## 3. Tools that build or show a system-level picture

### Takeaway
System-level pictures of an existing codebase are now free and common (DeepWiki, Google Code Wiki, Windsurf/Devin Codemaps), and architecture-as-code tools have added MCP servers so agents can read and write the model. These describe the system as it is; none found frames a single agent change as a before/after at system level tied to a developer's stated expectation. CodeSee, the best-known pre-AI codebase-map startup, shut down commercially and was absorbed by GitKraken.

### Cited Findings
- Devin Wiki / DeepWiki (Cognition): "Devin now automatically indexes your repos and produces wikis with architecture diagrams, links to sources, and summaries of your codebase"; a free version works with public GitHub repositories; `.devin/wiki.json` steers what is documented. — [Devin docs, DeepWiki](https://docs.devin.ai/work-with-devin/deepwiki) (official documentation, snippet only, undated; sells AI: yes). Claims of sequence/dependency diagrams and 50,000+ pre-indexed repos come from third-party guides and are unverified.
- Codemaps (Windsurf, now documented under Devin desktop): "shareable, hierarchical maps" showing the order in which code and files execute and how components relate; generated by a Codemap agent from a suggested topic or custom prompt; nodes open the file and function; shareable by link (stored on Cognition's servers, opt-in; off by default for enterprise); can be @-mentioned as agent context. The page does not say whether a Codemap reflects an agent's changes, and gives no plan or price. — [Devin docs, Codemaps](https://docs.devin.ai/desktop/codemaps) (official documentation, undated; sells AI: yes). The old Windsurf docs URL redirects there.
- Cognition acquired Windsurf (reported as December 2025, about $250M). — [nxcode](https://www.nxcode.io/resources/news/cognition-windsurf-acquisition-swe-1-5-codemaps-2026) (secondary, snippet only; date and price not verified against a primary source)
- Google Code Wiki: public preview from 13 November 2025 at codewiki.google, free for public repos; generates a wiki with architecture, class and sequence diagrams regenerated as code changes, plus Gemini chat. Private-repo support via a Gemini CLI extension was still waitlisted as of 6 May 2026. — [InfoQ, Nov 2025](https://infoq.com/news/2025/11/google-code-wiki/); [It's FOSS](https://itsfoss.com/news/google-code-wiki/) (secondary, snippet only; Google sells AI). A claim that it is open source rests on one tweet and is unverified.
- CodeSee: acquired by GitKraken, announced 14 May 2024, with code maps folded into GitKraken's DevEx platform. — [GitKraken press release](https://gitkraken.com/press/gitkraken-acquires-codesee-launches-devex-platform) (official, snippet only). A LinkedIn post attributed to the team says CodeSee would be "closing its doors and shutting down commercial operations on Thursday, Feb 22nd" — [LinkedIn](https://sk.linkedin.com/in/daniel-ivanyi-16845458) (anecdote, snippet only; year not shown, 22 February fell on a Thursday in 2024). An aggregator says it struggled to convert free users to paying customers. — [loot-drop](https://www.loot-drop.io/startup/2500-codesee) (secondary, low reliability)
- Sourcegraph: Sourcegraph and its coding agent Amp became separate companies, announced 2 December 2025; Sourcegraph continues as code search. — [Sourcegraph blog](https://sourcegraph.com/blog/why-sourcegraph-and-amp-are-becoming-independent-companies); [Amp](https://ampcode.com/news/amp-inc) (official, snippet only; both sell AI tools)
- Architecture-as-code with agents: Structurizr documents an MCP server with DSL validation, parsing and inspection; LikeC4 ships an MCP server so an agent can query the resolved model; IcePanel exposes a read/write MCP server and "drafts" for exploring changes without touching the live model. — [Structurizr docs, AI](https://docs.structurizr.com/ai); [LikeC4 MCP listing](https://mcp.so/servers/mcp-likec4); [IcePanel blog, 9 July 2026](https://icepanel.io/blog/2026-07-09-how-to-automate-your-architecture-diagrams) (official documentation / vendor blog, snippet only; IcePanel is paid SaaS)
- Research tool: Comprendia (ICSME 2026 tool demo; Nachuma and Zibran): an Eclipse plugin for Java combining a dependency graph, LLM explanations tied to visible graph nodes, clone detection and CVE overlays. Demonstration only; no user study reported in the abstract; open-source status not stated. — [arXiv 2608.10290](https://arxiv.org/abs/2608.10290) (study / tool paper, 10 August 2026; sells AI: no)

### Inferences
- Vendors treat the system-level picture as a navigation and onboarding aid ("understand this repo"), not as a check on a specific change or on the developer's own model.
- CodeSee's fate is a caution: maps of code alone did not sustain a business. A free open-source tool avoids the revenue problem but not the underlying question of whether people return to a map.
- Because LikeC4, Structurizr and Mermaid are open formats with agent access, the described tool could reuse them for the "what actually happened" diagram instead of inventing a format.

### Gaps
- Not verified in this session (no page opened): Swimm's current product, CodeScene, SciTools Understand, dependency-cruiser, Madge, Nx graph, ArchUnit, and Aider's "repo map". From background knowledge only, and therefore unverified here: dependency-cruiser, Madge, Nx graph and ArchUnit are open-source, deterministic, module-or-file-level dependency tools with no AI or learning element; Aider's repo map is context for the model, not a picture for the human. The report writer should treat these as uncited.
- Whether Codemaps, DeepWiki or Code Wiki diagrams are accurate: no independent evaluation found.
- Current Codemaps pricing and whether it is in the free tier: secondary sources conflict on Windsurf pricing and the docs page is silent.

## 4. Anything that asks the developer to predict, commit or answer before seeing the agent's result

### Takeaway
The nearest things that exist are (a) small open-source quiz gates that test the developer on a diff after the agent wrote it, (b) spec-first and plan-approval workflows where the developer commits to requirements, and (c) one strong academic prototype (Lead-and-Reveal / Trace-and-Predict) aimed at novices and code lines. I found no tool or paper in which a developer predicts the system-level effect of an agent's change beforehand and then sees a diagram of the actual effect beside it.

### Cited Findings

**Quiz gates on your own (agent-written) code: after the change, before commit or merge**
- lgtm-quiz (JoaoBRBR): MIT CLI that quizzes you on your branch's diff before commit or PR; optional git hook blocks the commit if you fail. Three question levels: "Mechanics" (what the code does with an input), "Decisions" (why written that way), "Architecture" (what else the change affects); default is levels 1 and 2. Keeps a per-concept confidence score in a local JSON profile that decays (halves after about 60 days) so known basics stop coming up. Claude Code only; other backends on the roadmap. Self-described as "a reminder, not a lie detector"; README admits the AI can write a bad question. 2 stars, 5 commits. No diagrams of the change. — [GitHub](https://github.com/JoaoBRBR/lgtm-quiz) (open-source project; undated; sells AI: no)
- PR Quiz (dkamm): GitHub Action that generates a quiz from a PR with an LLM and blocks merge until passed; code goes to OpenAI. Show HN on 29 July 2025, 94 points, 33 comments. — [Hacker News](https://news.ycombinator.com/item?id=44726672); [GitHub](https://github.com/dkamm/pr-quiz) (open-source project / anecdote; sells AI: no)
- pr-quiz (revodatanl): merge gate backed by Databricks; PR merges only when the quiz for the head commit scored 100%; a new commit resets it. — [GitHub](https://github.com/revodatanl/pr-quiz) (open-source project, snippet only)
- "Commit Comprehension Gate" (islandbytes): MIT GitHub Action generating multiple-choice questions from the diff before merge. — [DEV post](https://dev.to/islandbytes/i-built-a-merge-gate-that-quizzes-developers-on-their-own-code-changes-heres-why-and-how-5460) (anecdote / project post, snippet only)
- A DEV article on the same idea argues local hooks "are easy to bypass, can slow unrelated work, and often run before the developer has enough context", and recommends the PR or merge-queue level. — [DEV post](https://dev.to/vikassri/quizzing-developers-on-ai-generated-code-30o7) (opinion, snippet only)

**Spec-first and plan-approval workflows: before the change, but the commitment is to requirements, not a prediction**
- Birgitta Böckeler (Thoughtworks), 15 October 2025, tried Kiro, spec-kit and Tessl. On spec-kit: "To be honest, I'd rather review code than all these markdown files"; on Kiro for a small bug: "like using a sledgehammer to crack a nut"; on control: "I frequently saw the agent ultimately not follow all the instructions". She favours small iterative steps over heavy up-front specs. — [martinfowler.com](https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html) (opinion from hands-on trial; Thoughtworks is a consultancy, does not sell these tools)
- Secondary summaries describe community criticism of spec-kit as "a sea of markdown documents" and "waterfall with extra steps" for small tasks, with Kiro seen as lighter (three markdown files). — [codemyspec comparison](https://codemyspec.com/blog/spec-kit-vs-kiro); [rywalker research note](https://rywalker.com/research/github-spec-kit) (secondary / opinion, snippet only; codemyspec sells a competing tool)
- Plan modes (Cursor, Copilot, Claude Code; see section 2) ask the developer to approve the agent's plan before code is written. — [GitHub docs](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-plan-mode) (official, snippet only)

**Research prototypes**
- Kazemitabaar, Huang, Suh, Henley, Grossman, "Exploring the Design Space of Cognitive Engagement Techniques with AI-Generated Code for Enhanced Learning" (arXiv 2410.08922, 11 October 2024; published at IUI 2025 per ACM DOI): seven techniques requiring engagement "either before or after revealing the AI-generated code", tested with novices from intermediate CS courses (between-subjects N=82, then within-subjects N=42). Techniques include "Lead-and-Reveal" (the AI leads step by step, "prompting them to explain the necessary actions and decisions for each step before revealing the corresponding line of code"), "Trace-and-Predict" ("trace the code execution line by line with a sample input and predict value of variables"), "Explain-before-Usage", "Verify-and-Review" and "Solve-Code-Puzzle". — [paper PDF](https://austinhenley.com/pubs/Kazemitabaar2025IUI_AIFriction.pdf); [ACM](https://dl.acm.org/doi/10.1145/3708359.3712104) (study; sells AI: no)
- Results from that paper: in study 1 the learning gains of Lead-and-Reveal (b = 26.8, p = .058) and Trace-and-Predict (b = 21.8, p = .123) over baseline did not reach statistical significance; in study 2 Lead-and-Reveal "significantly improves alignment between perceived and actual coding ability without increasing cognitive load". The authors coin "Friction-Induced AI" and released the tool at lead-and-reveal.vercel.app. — [paper PDF](https://austinhenley.com/pubs/Kazemitabaar2025IUI_AIFriction.pdf) (study; sells AI: no)
- A null result: an Aalborg University master's project compared standard GitHub Copilot with a version that slowed suggestion acceptance and highlighted AI code (38 master's students) and found no statistically significant differences on any measure. — [Aalborg University](https://projekter.aau.dk/exploring-the-effect-of-friction-in-ai-programming-tools-on-cognitive-load-29d0e971.html) (student thesis, snippet only; not peer reviewed)
- LeetCoach (AAAI): a "reasoning-first" cognitive forcing design reported to foster incidental learning, with "temporary cognitive friction rather than immediate gains". — [AAAI proceedings](https://ojs.aaai.org/index.php/AAAI/article/view/42121/46082) (study, snippet only)
- A Springer 2026 article describes an LLM tool that generates comprehension questions about code for introductory programming students. — [Springer](https://link.springer.com/article/10.1007/s44230-026-00150-9) (study, snippet only; classroom context)

### Inferences
- The idea "make the developer prove understanding of agent-written code" has been independently built at least four times as open source since mid-2025, always as an after-the-fact gate on a diff with LLM-written multiple-choice questions. All have tiny adoption (2 stars to one 94-point HN post).
- lgtm-quiz is the nearest existing project on two of the described tool's features: it has an "Architecture" question level and a decaying per-concept skill profile. It differs on timing (after the change), on default level (code mechanics and decisions), on form (quiz with right answers, no diagram, no side-by-side) and on being a gate.
- The research closest to "predict then reveal" (Kazemitabaar et al.) supports the mechanism for calibration: the reveal-after-commitment technique improved the match between what people thought they could do and what they could do. But it studied novices, line-level code, and a chat tool. Whether it transfers to professionals predicting system-level effects of an agent's change is untested.
- Not all friction works: slowing acceptance and highlighting AI code did nothing measurable in one small study. Generative engagement (the user produces something) is what the positive results share.

### Gaps
- I found no CHI, UIST or ICSE 2025 to 2026 paper on system-level prediction before an agent acts. I searched by keyword, not by proceedings, so absence is not established. A proceedings-level search would be needed to state it firmly.
- Kiro and spec-kit were characterised from a hands-on essay and secondary posts; I did not open their current docs, pricing or licences (spec-kit is commonly described as open source by GitHub; Kiro as an AWS product; both unverified here).
- Test-first agent workflows (developer writes or approves tests before the agent codes): no source collected.
- Stars, commit dates and maintenance status of the quiz projects other than lgtm-quiz were not checked.

## 5. Developer sentiment: what developers say they want, and what they reject as friction

### Takeaway
Surveys show heavy use with conditional trust: developers trust agent output when they can check it easily and mostly keep agents supervised. Essays and forum threads describe a loss of the mental model of one's own system ("comprehension debt", "cognitive debt"). The things developers push back on are gates and paperwork: merge-blocking quizzes, piles of spec markdown, and review volume that turns into theatre.

### Cited Findings

**Surveys**
- Stack Overflow Developer Survey 2026 (about 30,900 respondents, per secondary coverage): 48.0% trust AI when they can easily check its output; 6.6% extend trust to important decisions; about 79% say source attribution matters when judging an AI answer; about 66% use coding assistants or agents; about 26% use automated agent workflows. — [IT Brief](https://itbrief.co.uk/story/stack-overflow-survey-finds-developers-wary-of-ai-tools); [The Register](https://www.theregister.com/a/5301662) (survey via secondary coverage, snippet only; Stack Overflow sells AI data products). I did not open Stack Overflow's own results page.
- Stack Overflow pulse survey, late April 2026, 1,100 developers and professionals (blog dated 27 May 2026): 60% block agents from making unapproved system changes; 63% rarely or never let agents run on autopilot; 68% prefer single-agent setups; accuracy and security are the top two concerns, though strong agreement that accuracy is a barrier fell from 57% to 47%. The blog calls human review the "gold standard". Daily agent use at work rose from 14% (2025) to 37% (2026) per the search summary. — [Stack Overflow blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work) (survey; Stack Overflow sells AI data products)
- JetBrains Developer Ecosystem Survey 2026 (published 19 August 2026; 15,000+ professional developers, May to July 2026): about 90% used coding agents at work at least weekly and 68% daily; agents fully generated about 47% of respondents' code on average. — [ITmedia @IT, 21 Sept 2026](https://atmarkit.itmedia.co.jp/ait/articles/2609/21/news019.html) (survey via Japanese secondary coverage, snippet only; JetBrains sells AI tools). The 2025 edition listed inconsistent code quality as the top AI concern — [JetBrains research blog, Oct 2025](https://blog.jetbrains.com/research/2025/10/state-of-developer-ecosystem-2025/) (survey, snippet only).

**Essays (opinion)**
- Addy Osmani, "Comprehension Debt" (14 March 2026): AI-generated code breeds false confidence because the codebase looks clean while understanding erodes; follow-up "Cognitive Surrender" (May 2026). — [addyosmani.com](https://addyosmani.com/blog/comprehension-debt/); [addyosmani.com](https://addyosmani.com/blog/cognitive-surrender/) (opinion, snippet only; author works at Google, which sells AI)
- Margaret-Anne Storey, "From Technical Debt to Cognitive and Intent Debt" (arXiv, March 2026): cognitive debt as team-level loss of shared understanding; intent debt as missing rationale. — [alphaXiv 2603.22106](https://www.alphaxiv.org/abs/2603.22106) (academic position paper, snippet only; sells AI: no)
- Böckeler on spec tools: would "rather review code than all these markdown files"; agents often did not follow the specs. — [martinfowler.com, 15 Oct 2025](https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html) (opinion)

**Forum threads (anecdote; individual comments, not representative)**
- Hacker News threads in 2026 ("Cognitive Debt: When Velocity Exceeds Comprehension", "Agentic coding is burning me out", "LLMs can be exhausting", "Six months of writing code exclusively with agents"): commenters say reviewing agent output means reconstructing what the agent was doing; that "the shared mental model of the team still advances at human speed"; that doing only review makes familiarity with the codebase decay even when reading everything; that volume makes review feel like theatre; and that debugging depends on a mental model of the code. A counter-view: agent-assisted review helps build a mental model quickly. — [HN 47196582](https://news.ycombinator.com/item?id=47196582); [HN 47962775](https://news.ycombinator.com/item?id=47962775); [HN 47391803](https://news.ycombinator.com/item?id=47391803); [HN 49465119](https://news.ycombinator.com/item?id=49465119) (anecdote, snippet only; I did not open the threads, so wording is from search summaries and attribution to a specific thread is approximate)
- Reactions to the PR Quiz merge gate (HN, 29 July 2025): for: "We've got a huge LGTM problem"; "This could actually be quite useful". Against: "Cute but I wouldn't actually use it"; people will "just get AI to answer the quiz instead"; it "assumes that LLMs know what they're coding"; privacy objections to sending code to a model provider; and the point that review and comprehension checks serve different purposes. — [Hacker News](https://news.ycombinator.com/item?id=44726672) (anecdote)
- In the (Im)Paired Programming preprint, students "reported weaker understanding but still preferred coding agents because they are fast and easy to use". — [arXiv 2607.26375](https://arxiv.org/abs/2607.26375) (study, preprint)

### Inferences
- What developers say they want maps to: being able to verify cheaply, keeping approval over consequential changes, and keeping a working mental model of the system. The mental-model complaint is specifically at system level ("my own codebase"), which matches the described tool's level.
- What gets rejected: anything that blocks shipping (gates), anything that adds reading (spec files, long explanations), and anything that can be gamed by handing it to the AI. A tool for this audience should probably be opt-in, short, non-blocking, and produce something the developer finds useful in its own right (the diagram), not a score.
- The stated preference for speed even when people know they understand less (preprint, students) suggests voluntary adoption of any effortful step will be low unless the cost is very small. This is a risk to state plainly.

### Gaps
- No survey question found that asks developers directly what they want in order to understand agent work, or whether they would accept a prediction step. Sentiment here is assembled from adjacent questions and anecdotes.
- Reddit threads were not collected.
- Stack Overflow 2026 and JetBrains 2026 figures are from secondary coverage; primary result pages were not opened.
- Secondary sources cite a 2026 study in which developers accepted faulty AI reasoning 73.2% of the time; I could not trace it to a primary source and did not use it.

## 7. The gap: what nobody does yet, and the nearest competitors to the described tool

### Takeaway
Stated carefully: among the products, open-source projects and papers found on 16 November 2026, none combines (1) a developer-authored prediction made before the agent acts, (2) at system level only, (3) a diagram of the actual change set beside that prediction, and (4) a record of the developer's skill over time. Each element exists somewhere separately. This is a finding of "not found in a keyword-level search", not proof of absence.

### Cited Findings
- Element 1, commit before reveal: exists in research for novices at line level (Lead-and-Reveal, Trace-and-Predict), not for agents or system level. — [Kazemitabaar et al.](https://austinhenley.com/pubs/Kazemitabaar2025IUI_AIFriction.pdf) (study)
- Element 2 and 3, system-level diagram of a change: exists after the fact in CodeRabbit (sequence diagrams on PRs, default on) and visual-explainer (`/diff-review` "architecture comparison"); exists before the fact for the agent's plan in claude-plan-visualizer and Cursor Plan Mode. — [CodeRabbit docs](https://docs.coderabbit.ai/pr-reviews/walkthroughs); [visual-explainer](https://github.com/nicobailon/visual-explainer); [claude-plan-visualizer](https://github.com/omril321/claude-plan-visualizer); [Cursor changelog](https://cursor.com/changelog/2-2)
- Plan-versus-built comparison: visual-explainer's `/generate-visual-plan` includes "a view of what was built afterward"; claude-plan-visualizer explicitly does not compare plan with result. Neither involves the developer's own prediction. — [visual-explainer](https://github.com/nicobailon/visual-explainer); [claude-plan-visualizer](https://github.com/omril321/claude-plan-visualizer)
- Element 4, skill over time: lgtm-quiz keeps a decaying per-concept confidence profile locally; no other tool found keeps any model of the developer. — [lgtm-quiz](https://github.com/JoaoBRBR/lgtm-quiz)
- Vendor learning modes do not fill the gap: Claude Code Learning operates at code-line level during the change with no memory and no enforcement. — [Claude Code docs](https://code.claude.com/docs/en/output-styles)
- The need is argued by vendor and independent research alike: comprehension falls with delegation (Anthropic RCT; (Im)Paired Programming preprint), and the Anthropic authors expect larger effects with agents. — [Anthropic](https://www.anthropic.com/research/AI-assistance-coding-skills); [arXiv 2607.26375](https://arxiv.org/abs/2607.26375)

### Inferences

Nearest competitors, in order of closeness (my judgement):

1. **lgtm-quiz** (open source, MIT, Claude Code). Shares: developer must answer about an agent's change; an architecture level exists; skill profile over time; free. Differs: after the change; defaults to code mechanics; quiz with right/wrong, not a prediction compared with a diagram; can block commits. Adoption negligible (2 stars), so it is a design precedent more than a competitor.
2. **visual-explainer** (open source, MIT, 11.1k stars, many agents). Shares: system-level visuals of plan and of what was built; free; cross-agent. Differs: the developer is a reader and decision-maker, never a predictor; no skill record. It is the strongest incumbent for "show me a diagram of what the agent did", and could add a prediction step cheaply. This is the main competitive risk.
3. **Learning Opportunities** (open source, Claude Code and Codex, by a known researcher). Shares: deliberate skill-building around agent work, triggered by architectural changes. Differs (as far as verified): after the change; exercise format unknown. Needs direct reading before the report asserts a difference.
4. **Claude Code Learning style** and plan modes (built in, zero install). Share: the "pause and involve the human" moment, and the before-change slot. Differ: code lines or agent-authored plan; no comparison; no memory. Their advantage is distribution: a vendor could ship a "predict first" variant as a style or plan-mode option.
5. **CodeRabbit walkthrough / Change Stack** (paid, PR-time). Shares: diagram of what actually changed at component level. Differs: after, at PR, for reviewers, no developer input.
6. **PR quiz gates** (open source). Share the comprehension-check intent; differ on everything else and show the reception risk for anything that blocks.

Other points for the report writer:

- The defensible novelty is the pairing, not the parts: prediction by the developer, before, at system level, with the actual outcome drawn beside it. Diagrams of changes and quizzes on diffs are already commoditised.
- Evidence for the mechanism is suggestive, not established: one study (novices, line level) found reveal-after-commitment improved calibration; learning gains there were not statistically significant in the first study; one small study of passive friction found nothing. No evidence exists for professionals, agents, or system-level prediction. Any claim that the described tool "works" would be unsupported today.
- Reception risks seen in the sources: gates are disliked and gamed ("just get AI to answer the quiz"); extra reading is rejected (spec markdown); LLM-written questions and diagrams can be wrong; users prefer speed even when they know they understand less. An optional, non-blocking, short prediction with a useful artefact (the diagram) avoids the first two but still faces the last.
- A technical dependency worth flagging: the tool is only as good as the "what actually happened" diagram. No independent evaluation of the accuracy of LLM-generated change diagrams was found for any tool.

### Gaps
- Absence claims rest on roughly 40 searches and page reads on one day. I did not search conference proceedings systematically, GitHub by topic exhaustively, VS Code or JetBrains marketplaces, or non-English sources. A tool matching the description could exist with low visibility.
- Learning Opportunities' actual exercise design is unverified and could narrow the gap (for example if it already asks for predictions).
- I did not check whether any vendor has announced or previewed a predict-first feature (roadmaps, betas, conference talks).
- No data on how many developers actually turn on Explanatory or Learning styles, study mode for code, or any quiz tool; usage of existing learning features is unknown, so demand for the described tool is inferred, not measured.
